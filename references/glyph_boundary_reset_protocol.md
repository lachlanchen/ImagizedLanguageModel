# Does clearing drawing memory recover unseen combinations?

The shared visual controller copied 3,514 first glyphs but only 159 two-glyph prefixes and no complete unseen strings. Test the frozen controller and writer without optimization. Use the original 3,845 expressions and the same 3,845 unseen permutations. Feed the four target glyph images to both arms. For each glyph use the trained controller, four-path beam and twelve four-bit physical decisions. Mask stop in both arms and supply the four boundaries and length externally. At each boundary, commit the highest-scoring complete glyph, remove the other paths and reset the beam scores. One arm carries the winner's GRU state, final pattern and actual rendered feedback. The other sets hidden state to the supplied next-glyph state, previous pattern to start and feedback to zero as at the beginning of a string. Neither arm uses a glyph inventory to decode. Require first-position bitmaps to agree for every expression in both sets. Check complete and per-position exactness, and rare observed expressions separately. This isolates the combined history reset under matched glyph commitment. It cannot isolate each history channel or validate stopping.

A useful physical interface should reach at least 90% complete on seen, rare and new strings and improve new-string accuracy over the carry arm. Otherwise use position-specific correctness and the measured direct-landmark renderer ceiling to decide whether the planner should control physical landmarks directly. Run on one 4090 D with two CPU threads, at most 120 seconds and 1 GiB allocated GPU memory. Record both outcomes and all emitted pixels. No autonomous language claim follows from supplying images to copy.
