# Chinese idiom writing from pictured context

## Writing a missing expression

The current 2.12M-parameter Chinese writer reads up to 24 pictured cells on either side of a gap and draws its answer. It completed 433 of 17,555 independently held-out gaps exactly, versus 276 for the preceding writer and 789 for a local count baseline. This CPU example produces **一举一动**. Use a new output directory for each run. [Results and failure example](../../references/expression_preference_result.md)

```bash
python -m scripts.infer_pictured_idiom \
  --weights models/pictured_idiom_zh/reader_writer.safetensors \
  --writer models/pictured_idiom_zh/joint_reference_writer.safetensors \
  --before-text '【广东行情】苹果的本本，其' \
  --after-text '都备受关注，如果要是在价格上有什么□，那肯定是一' \
  --output /tmp/ilm-joint-answer
```

The output directory contains `answer.png`, packed pixels in `answer.bin` and a stop receipt. To use pictured input, pass `--before-image` and `--after-image` with black-on-white, row-major grids of 32-pixel cells.

## Reading historical forms from a plate

This optional 2.65M-parameter configuration reads a pictured Chinese or English question and four rows of labelled historical evidence. Each row is five 32-pixel cells wide. It accepts oracle, bronze, seal and liushu or their pictured Chinese names 甲骨文、金文、篆書、六書通. The answer contains the selected source pixels in the requested order. On a fresh CPU process the example below returned the oracle form J04919 and bronze form B02976 of 言. These examples use the same 32-pixel font and layout as training. [Held-out tests and limitations](../../references/historical_plate_result.md)

```bash
python -m scripts.infer_pictured_idiom \
  --weights models/pictured_idiom_zh/reader_writer.safetensors \
  --writer models/pictured_idiom_zh/joint_reference_writer.safetensors \
  --source-reader models/pictured_idiom_zh/historical_reader.safetensors \
  --question-text 'Show 言: oracle, bronze' \
  --plate-image models/pictured_idiom_zh/examples/yan_plate.png \
  --output /tmp/ilm-yan-forms
```

For a held-out image-only request, pass `--question-image models/pictured_idiom_zh/examples/ma_question.png` and `--plate-image models/pictured_idiom_zh/examples/ma_plate.png`. The receipt records the chosen route, output length and stop. The same three weights also accept the modern passage inputs shown below.


## Earlier reader-guided writer

The reader-guided writer produced 378 exact development expressions in 22,907 gaps and 163 in 9,135 previously unused gaps. A local count model produced 1,012 and 406. To use the guided writer on CPU, pass the base checkpoint and its updated writer weights. The following passage produced **风风雨雨** in a fresh process.

```bash
PYTHONPATH=. python -m scripts.infer_pictured_idiom \
  --weights models/pictured_idiom_zh/reader_writer.safetensors \
  --writer models/pictured_idiom_zh/distilled_writer.safetensors \
  --before-text 'MBA在美国经历了百年的' \
  --after-text '，有着很强的生命力。投资的准备与收获当我们决定投' \
  --output /tmp/ilm-guided-answer
```

The output directory should be new. It will contain the model's physical answer image, its packed bytes, and its stop decision. The training-only teacher and its answer inventory are unnecessary for inference. [Matched comparison and held-out results](../../references/visual_writer_transfer_result.md)

## Initial aligned writer

This checkpoint contains a 2,115,971-parameter reader and writer. It predicts an omitted expression between two pieces of pictured Chinese prose. It was trained on 71,439 candidate-free ChID windows and uses a learned physical renderer. The model has a single cloze task. It does not generate an explanation of an idiom.

With NumPy, PyTorch, Pillow, fontTools and safetensors available, run from the repository root. The example is a published validation case. Its reference and model output are 轻举妄动.

```bash
PYTHONPATH=. python -m scripts.infer_pictured_idiom \
  --weights models/pictured_idiom_zh/reader_writer.safetensors \
  --before-text '否雄起，还要看政策、全球经济等多方脸色，我们不敢' \
  --after-text '。灵活操作依然是首选。”一保险资产管理公司的负责' \
  --output /tmp/ilm-idiom-answer
```

The command writes `answer.png`, packed `answer.bin`, and a stop receipt. It runs on CPU. Typed Chinese uses Noto Sans CJK to render the input. Existing black-on-white 32-pixel cells can be passed as `--before-image` and `--after-image`; each side uses up to 24 cells. All answer pixels are generated by the checkpoint. No corpus, search engine, candidate list or output font is used at inference.

The model got 134 exact complete answers on 22,907 validation gaps. Exchanging the contexts yielded 23. A local training-count baseline yielded 1,012. The trained reader can also be evaluated against supplied answers, which is a different deployment. See the [full results](../../references/pictured_idiom_result.md) and [corpus description](https://aclanthology.org/P19-1075/).

### Answer questions about a pictured passage

The optional mixed reader takes an ordered passage and a separate question, each supplied as text or as an image grid of 32-pixel cells. It learns to return a variable-length interval of source ink or use the existing recurrent expression writer. On the official Chinese reading split it returned 1,000 accepted complete answers across 3,219 questions, including 49 inputs outside the preparation font. It can write a missing expression when the gap is centred between the two 24-cell halves of a passage. Arbitrary prose generation remains open. [Measurements and limits](../../references/mixed_ink_reading_result.md)

```sh
python -m scripts.infer_mixed_ink \
    --passage-image passage.png --passage-cells 453 \
    --question-image question.png --output answer
```

The command runs on CPU and writes the image, packed ink and decision receipt. Use the cell count to exclude final padding on a multirow image. Typed input uses the training font. The source route copies the original supplied pixels.
